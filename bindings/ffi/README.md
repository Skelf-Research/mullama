# Mullama FFI — C ABI for embedding local LLM inference in any language

[![Crates.io](https://img.shields.io/crates/v/mullama-ffi)](https://crates.io/crates/mullama-ffi)
[![License](https://img.shields.io/badge/license-MIT_OR_Apache--2.0-blue.svg)](https://github.com/cognisoc/mullama/blob/main/LICENSE)

## What is Mullama FFI?

`mullama-ffi` is a stable C ABI layer over the [Mullama](https://github.com/cognisoc/mullama) Rust core, exposing `llama.cpp`-backed GGUF inference as a plain C library. It produces both a shared library (`libmullama_ffi.so` / `.dylib` / `.dll`) and a static library (`.a` / `.lib`), plus a generated C header (`mullama.h`), so you can call Mullama from C, C++, or any language with FFI support — without writing your own bindings to `llama.cpp` from scratch.

This is the same library the official Mullama bindings for Python, Node.js, Go, and PHP all consume. Use it directly if you're embedding a local LLM in a C/C++ application (game engine, native desktop app, server runtime, kernel module), or if you're building a new language binding.

## Why use `mullama-ffi` over rolling your own llama.cpp FFI?

| | `mullama-ffi` | DIY `llama.cpp` FFI |
|---|:-:|:-:|
| Stable, versioned C ABI | ✓ | follows `llama.cpp` upstream |
| Memory-safe handle management (Arc + drop) | ✓ | manual |
| Thread-local error messages (`mullama_get_last_error`) | ✓ | none |
| Callback-based streaming with cancellation token | ✓ | manual |
| Pre-built shared library for 6 platforms | ✓ | build it yourself |
| One header (`mullama.h`) covers model, context, sampler, embeddings, multimodal | ✓ | several headers, plus your own glue |
| Higher-level concepts (chat templates, sampler presets) baked in | ✓ | no |

## Install

### Pre-built (recommended)

Every Mullama GitHub release attaches a `mullama-ffi-<version>-<target>.tar.gz` for each supported platform. The tarball contains `lib/libmullama_ffi.<so|dylib|dll>` and `include/mullama.h`.

Targets shipped today:

- `x86_64-unknown-linux-gnu` (+ `-cuda` variant for NVIDIA CUDA)
- `aarch64-unknown-linux-gnu`
- `x86_64-apple-darwin`
- `aarch64-apple-darwin` (Metal)
- `x86_64-pc-windows-msvc`

### Build from source

```bash
git clone --recurse-submodules https://github.com/cognisoc/mullama.git
cd mullama
cargo build --release -p mullama-ffi
# Output:
#   target/release/libmullama_ffi.{so,dylib} (Unix)
#   target/release/mullama_ffi.dll (Windows)
#   target/release/libmullama_ffi.a (static, Unix)
#   bindings/ffi/include/mullama.h (regenerated by cbindgen)
```

For GPU acceleration, set the relevant env var before `cargo build`:

| Backend | Env var |
|---|---|
| CUDA | `LLAMA_CUDA=1` |
| Metal | `LLAMA_METAL=1` |
| ROCm | `LLAMA_HIPBLAS=1` |
| Vulkan | `LLAMA_VULKAN=1` |
| OpenCL | `LLAMA_CLBLAST=1` |
| SYCL | `LLAMA_SYCL=1` |

## Quick start

```c
#include <mullama.h>
#include <stdio.h>

int main(void) {
    mullama_backend_init();

    MullamaModelParams mparams = mullama_model_default_params();
    mparams.n_gpu_layers = 32;
    MullamaModel* model = mullama_model_load("./llama3.2-1b.gguf", &mparams);
    if (!model) {
        fprintf(stderr, "load failed: %s\n", mullama_get_last_error());
        return 1;
    }

    MullamaContext* ctx = mullama_context_new(model, NULL);

    int32_t tokens[1024];
    int n_tokens = mullama_tokenize(model, "What is the capital of France?",
                                    tokens, 1024, true, false);

    char out[4096];
    mullama_generate(ctx, tokens, n_tokens, 100, NULL, out, sizeof(out));
    printf("%s\n", out);

    mullama_context_free(ctx);
    mullama_model_free(model);
    mullama_backend_free();
    return 0;
}
```

Compile and link:

```bash
gcc main.c -I/path/to/include -L/path/to/lib -lmullama_ffi -o demo
LD_LIBRARY_PATH=/path/to/lib ./demo
```

## Streaming with cancellation

```c
bool on_token(const char* token, void* user_data) {
    fputs(token, stdout);
    fflush(stdout);
    return true;  // return false to stop generation
}

MullamaCancelToken* cancel = mullama_cancel_token_new();
mullama_generate_streaming_cancellable(
    ctx, tokens, n_tokens, 256, NULL,
    on_token, NULL, cancel);
// From another thread: mullama_cancel_token_cancel(cancel);
mullama_cancel_token_free(cancel);
```

## Embeddings

```c
MullamaEmbeddingGenerator* gen = mullama_embedding_generator_new(model, NULL);
int n_embd = mullama_embedding_generator_n_embd(gen);

float* v1 = malloc(n_embd * sizeof(float));
float* v2 = malloc(n_embd * sizeof(float));
mullama_embed_text(gen, "How do I cook pasta?",                v1, n_embd);
mullama_embed_text(gen, "What's the best way to boil noodles?", v2, n_embd);

float sim = mullama_embedding_cosine_similarity(v1, v2, n_embd);
printf("similarity = %f\n", sim);

mullama_embedding_generator_free(gen);
free(v1); free(v2);
```

## Error handling

All functions that can fail return `NULL` (for pointer returns) or a negative `int` (for status returns). Use `mullama_get_last_error()` immediately afterwards — the message is thread-local, so the call is safe in multi-threaded code:

```c
MullamaModel* model = mullama_model_load("nonexistent.gguf", NULL);
if (!model) {
    fprintf(stderr, "Failed to load: %s\n", mullama_get_last_error());
}
```

## Thread safety

- `MullamaModel` handles are thread-safe and can be shared across threads (internal Arc reference counting).
- `MullamaContext` handles use internal locking; concurrent calls on the same context serialize.
- Error messages are thread-local — `mullama_get_last_error()` returns the last error from the current thread only.
- Backend init/free is global; call `mullama_backend_init()` once at startup, `mullama_backend_free()` once at shutdown.

## Memory management

- Every `mullama_*_new` / `_load` / `_clone` returns a handle that must be released via the matching `mullama_*_free`.
- `mullama_model_clone` / `mullama_context_clone` increment Arc refcounts; cheap to use for shared ownership.
- Output string buffers are supplied by the caller; the library writes into them and returns the byte length (or a negative status code if the buffer was too small).

## FAQ

### Is the C ABI stable?

Yes within a minor version. Mullama follows semver: breaking ABI changes only land on a major bump. Within `0.3.x` you can drop in a newer `libmullama_ffi.so` against an existing binary.

### Is this the same numerical kernel as `llama.cpp`?

Yes. Mullama uses `llama.cpp` as a git submodule and links against it. The C ABI is the Mullama-flavoured surface; the matrix math is identical.

### Can I link statically?

Yes — `cargo build --release -p mullama-ffi` produces `libmullama_ffi.a` alongside the shared library. The static archive embeds `libllama.a` and `libggml.a` from the submodule.
